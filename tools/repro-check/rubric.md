# Rubric: is this reproduction package ready to post?

## Checks

| Check            | Evidence                                                                                                                                                               | Pass condition                                                                                                                                                                                                                         | Weight    |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `environment`    | The **repro report's Environment record**, read against the **issue context's stated version, OS, installation method, and other relevant target conditions**          | Pass if the environment information is sufficient to determine whether the reported issue was tested under relevant conditions; differences from the issue's environment must be identified when they materially affect reproduction   | required  |
| `steps` | The **repro report's Steps/Preparation/Execution sections**, read against the **issue's reproduction scenario, inputs, commands, and relevant starting state** | Pass if a stranger could follow the stated steps to **attempt the reported scenario**, including when the attempt ends in a documented cannot-reproduce result; the steps must be concrete enough to establish what was actually tested | required |
| `behavior_shown` | The **repro report's output excerpts, logs, screenshots, or other artifacts**, read against the **issue description's reported actual behavior and expected behavior** | Pass if the evidence demonstrates either **(a) the same core behavior described by the issue, or (b) a concrete, directly observed result of an attempted reproduction that clearly shows the reported behavior did not occur**. For a cannot-reproduce result, the report must provide enough observed output/artifacts to establish what happened and explicitly distinguish the observed result from the issue's reported behavior. A different error, adjacent failure, or unsupported inference does not pass | required |
| `honesty` | The **candidate claim comment and repro report**, especially claims compared with the **observed artifacts** | Pass if the candidate's claims accurately reflect what the evidence establishes, including honestly reporting a cannot-reproduce result. A candidate must not claim that the issue was reproduced when the evidence only establishes that an attempted reproduction failed. Unsupported causes, prevalence claims, or conclusions must not be presented as observed facts | required |
| `comms` | The **candidate claim comment**, **issue context**, **repo-facts contribution policy**, and any stated **AI-use/disclosure requirements** | Pass if the candidate communicates specifically about the issue, follows applicable repository conventions or disclosure requirements, and at the claim stage promises an investigation/report rather than asserting that reproduction has already occurred; repo-specific requirements take precedence over generic communication expectations | required |

## Verdict rule

Accept if every required check passes. Preferred checks never change
the verdict. If a required check is unclear or cannot be verified from
the available evidence, treat it as fail and reject.
